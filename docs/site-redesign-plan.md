# 活動報告サイト 再設計プラン

最終更新: 2026-07-25

## 目的

このサイトの主役は、企画の抽象的な世界観ではなく、2026年春に学生が何を考え、作り、失敗し、本番へ持っていったかという活動記録です。

最初にタイムラインを読み、必要に応じて写真・動画・技術の詳細へ入れる構成にします。現在のサイトの改修は、このプランと素材選定を確認してから行います。

## 参考にする二つの方向

### OCRリポジトリから引き継ぐもの

参照: [2026HCD-memory-map-ocr](https://github.com/novelsavage/2026HCD-memory-map-ocr)

- 温かいオフホワイトの背景、黒に近い文字、黄色とオレンジのアクセント
- 2px程度の輪郭線、角を丸めすぎないパネル、少しずらした硬い影
- 方眼、日付コード、小さな状態表示など、作業道具らしい表現
- 見出しやラベルに使うドット／ビット系の書体
- 「かわいい未来感」より、実際に現場で使う操作画面の率直さ

ただし、フォームや管理画面の密度をサイト全体へそのまま移しません。この表現はカレンダー、タイムラインのラベル、技術詳細など「情報を読む部分」に限定します。

### NEOのサイトから引き継ぐもの

参照: [NEO Home Robot](https://www.1x.tech/neo)

- 最初の一画面を、本物の写真または動画に任せる
- ナビゲーションと説明を小さくし、素材の上に文章を載せすぎない
- 一つの画面に一つの話題を置き、短い文章と大きな映像を交互に見せる
- カードを大量に並べず、余白と画面の切り替わりで章を分ける
- 動きは素材を見るために使い、装飾そのものを見せ場にしない

## デザイン原則

1. 実物が先、説明は後
   写真、画面録画、手書き付箋、地図、模型など実在する素材を優先します。

2. 一文に一つの事実
   「記憶」「つながる」「未来」といった抽象語を重ねず、誰が読んでも同じ意味になる言葉を使います。

3. 成功だけで編集しない
   迷った点、やり直した点、進め方を変えた点を、成果と同じ時間軸に載せます。

4. UIの意匠に役割を持たせる
   黄色は達成、オレンジは苦労、黒は本番、細い線は通常の活動に使います。色を単なる飾りにしません。

5. 素材がない場所を飾らない
   ストック写真、意味のない3Dオブジェクト、生成画像で穴を埋めません。

## ページ構成

### 1. ファーストビュー

- Home Coming Day当日の映像、または会場全景の写真を全画面で表示
- 左上に小さく `2026 / 思い出マップ自主企画ゼミ`
- 画面下に事実だけを一文で表示
  - 案: `卒業生の思い出を集め、古地図とデジタル地図に表示する展示をつくった。`
- 主ボタンは `活動を時系列で見る` の一つだけ
- 動画は自動再生する場合、無音・ループ・停止操作を用意する

### 2. 概要

活動期間、場所、目的、実施日、制作物を、短い表として載せます。大きな数字のKPIカードにはしません。

### 3. 活動タイムライン

このページの中心です。

```text
┌──────────────┬──────────────────────────────────┐
│  APR  MAY    │  04.15  ゼミが始動               │
│  小型         ├──────────────────────────────────┤
│  カレンダー ●─┼──04.29  二つの班に分かれる       │
│  JUN  JUL     │          決定 / 全体              │
│               │          やったこと…              │
│         ○─────┼──06.17  投稿がUnityへ届く         │
│               │          苦労 / 達成 / 技術        │
└──────────────┴──────────────────────────────────┘
```

#### デスクトップ

- 左側: 4〜7月の小型カレンダーを固定表示
- 右側: 日付順の活動記録
- 現在読んでいる項目の日付を左のカレンダーで強調
- カレンダーの日付から該当項目へ、細いSVG線を引く
- 通常活動は細い黒線、苦労はオレンジ、達成は黄色、本番は太い黒線
- 線が交差しすぎないよう、一度に強調する線は現在の項目だけにする
- 重要でない日付は短くまとめ、達成点や本番には写真・動画を大きく置く

#### モバイル

- 左右二列をやめ、上部に横スクロールできる月・日付レールを固定
- 本文左端に一本の縦線を置き、選択日だけ日付レールと連動
- 複数の接続線は表示しない
- 写真と動画は画面幅いっぱいにする

#### 1項目の構造

1. 日付とラベル
2. 事実を表す短いタイトル
3. `やったこと`
4. 必要な場合だけ `決まったこと` `困ったこと` `できたこと`
5. 写真、動画、画面録画、成果物
6. 次の活動へどう影響したか

文章と項目の詳細は [activity-timeline.md](./activity-timeline.md) を正とします。

### 4. 本番

### 5. 技術の試行錯誤

全技術を同じ大きさで紹介せず、証拠素材のある三つ程度に絞ります。

- 手書き付箋を撮影して、確認後に公開するまで
- 緯度経度をUnity座標へ合わせるまで

- 素材が十分なら、7月のThree.jsビューアも追加

成功画面だけでなく、位置ずれや取り下げた表示も比較できるようにします。

その直後に、オープンキャンパスへ何を変えて持っていくかを置きます。

## ビジュアル仕様

### 色

OCR画面を起点に、次を暫定値とします。

```css
--paper: #f7f3ea;
--panel: #fffaf0;
--ink: #192024;
--muted: #687076;
--line: #232323;
--achievement: #f2c94c;
--struggle: #e86f43;
```

- 背景全体は基本的に無地
- 方眼はカレンダーと技術情報の背景だけに使う
- 写真の上に黄色やオレンジのグラデーションを被せない
- ダーク背景は本番や映像の章の切り替えに限定する

### 文字

- 日付、状態ラベル、短い章番号: OCRリポジトリと同系統のビット／ドット書体
- 長い日本語本文: 可読性の高いゴシック体
- 大見出しを過度に巨大化しない
- 英単語を雰囲気のためだけに添えない

### 形

- 情報パネル: 2pxの線、0〜8px程度の小さな角丸、硬い影
- 写真・動画: 原則として枠なし、または細い線のみ
- ボタン: 塗りつぶしは主操作だけ
- アイコン: 意味が本文と重複する場合は置かない

### 動き

- ファーストビューの動画
- タイムラインを読む位置に応じたカレンダーの日付更新
- 現在の項目へ接続線が伸びる短い動き
- 画像の控えめな表示切り替え

パーティクル、常時動く背景、強いパララックス、文字が一文字ずつ現れる演出は使いません。

## 文章方針

話を大きく見せるコピーより、現場の具体性を優先します。

| 避ける表現 | 採用する表現 |
| --- | --- |
| 思い出を、もう一度その場所へ。 | 2026年春、卒業生の思い出を集める展示をつくった。 |
| 記憶が地図の上で立ち上がる。 | 投稿された場所に、思い出の文章を表示した。 |
| 展示を支えた、見えないリレー。 | 付箋を撮影してからUnityに表示されるまで。 |
| 数々の壁を乗り越えた。 | 座標がずれた原因は、Unityの単位設定だった。 |

本文の基本形は「何をした」「何が起きた」「次にどう変えた」です。参加者の感情は、記録や本人の言葉で確認できる場合だけ記載します。
