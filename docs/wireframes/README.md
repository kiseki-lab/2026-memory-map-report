# 活動報告サイト ワイヤーフレーム

再設計プランを、実装前にページの長さと情報の強弱を確認できる形へしたものです。色、写真、書体、細かな余白は未決定です。

- [モバイル版](./mobile.svg)

## この段階で確認すること

1. 活動報告がページの中心に見えるか
2. カレンダーとタイムラインの関係が分かるか
3. 本番写真と技術的達成の置き場所が適切か
4. 振り返りまで読んだとき、成功談だけに見えないか

## デスクトップの考え方

- ファーストビューは当日の写真または動画を画面いっぱいに置く
- タイムラインでは左のカレンダーを固定し、右の記録だけが流れる
- 読んでいる記録の日付と、カレンダーの日付を一本の線で結ぶ
- 6月17日の技術的達成と6月20日の本番は、通常項目より大きく扱う
- 本番と技術詳細では、文章のカードを並べず映像を主役にする

## モバイルの考え方

- 左右二列にはせず、月と日付を横に動かせるレールへ変える
- 現在の日付レールはタイムライン区間だけ上部へ固定する
- 接続線は一本の縦線へ簡略化する
- 写真・動画は画面幅いっぱいにする

## 想定する操作

### カレンダーから探す

日付を選ぶと、対応する活動記録までスクロールします。記録が複数日にまたがる場合は開始日を選択点にします。

### スクロールして読む

各項目が基準位置へ入ると、カレンダーの選択日と接続線が更新されます。全日付の線を同時に表示しないため、配線が混雑しません。

### メディアを見る

動画には再生・停止、ミュート状態、キャプションを用意します。自動再生が利用できない環境では静止画を表示します。

## タイムラインの表示密度

| 表示 | 対象 |
| --- | --- |
| 小 | 準備、環境整備、日程調整 |
| 中 | 方針決定、アナログ制作、OCR検証 |
| 大 | 6月17日のリアルタイム表示、6月20日の本番、7月5〜6日のWebビューア試作 |

詳細な内容は [活動タイムライン](../activity-timeline.md)、デザイン方針は [再設計プラン](../site-redesign-plan.md)を参照します。

## 実装時の境界

- ワイヤーフレーム内の写真枠は枚数の目安であり、ダミー画像を公開サイトへ残さない
- カレンダー連動はJavaScriptが無効でも、通常の時系列記事として読める構造にする
- `prefers-reduced-motion` では線のアニメーションと自動スクロールを止める
- 個人が写る写真と投稿内容は、公開可否を確認してから使用する
